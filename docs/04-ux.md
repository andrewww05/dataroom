# 04 — UX

Tailwind v4 for layout and tokens, shadcn/ui (Radix under it) for the fifteen or so primitives that
would otherwise be hand-rolled — dialog, dropdown menu, context menu, tooltip, toast, progress,
skeleton, breadcrumb, table, input, button, checkbox, tabs, scroll area, popover. shadcn components
are copied into the repo, so there is no theme algorithm to fight and no vendor look to override:
the design tokens are ours. Desktop is the primary target — below 900 px the tree and the details
pane become sheets behind toolbar buttons, and the listing keeps the full width.

The head of the tree and of the breadcrumbs is the Data Room's name (FR-ROOM-010) — editable in
place from the tree head, never the word "Root". The details pane appears only when exactly one item
is selected; with several selected it is replaced by a count and the bulk actions, with none, by the
Data Room's own stats.

## Interactions

| Gesture                              | Result                                                                                           |
| ------------------------------------ | ------------------------------------------------------------------------------------------------ |
| Single click                         | Select; replaces the selection                                                                   |
| **Double click**                     | **Folder: open it. File: open the viewer** (FR-VIEW-060) — never a download                      |
| Ctrl/⌘ + click                       | Add or remove one item _(Polish)_                                                                |
| Shift + click                        | Range from the anchor _(Polish)_                                                                 |
| Right click                          | Context menu for the item under the cursor, selecting it first if it was not selected _(Polish)_ |
| Right click on empty space           | Menu for the current folder: New folder, Upload, Paste _(Polish)_                                |
| Drag onto the listing or a tree node | Upload there                                                                                     |
| Drag an item onto a folder           | Move it there (FR-FILE-050's other half)                                                         |

Download is a toolbar button, a context-menu entry and a button inside the viewer. It is never what
happens when you open something — that was the single biggest UX error in the previous draft of this
file, and it is exactly the muscle memory Drive and Dropbox have trained.

The toolbar and the context menu offer the same actions and both disable what the selection does not
allow — Download and Open are file-only, Share is single-selection-only, Paste appears only when the
clipboard holds something (FR-VIEW-030).

## Keyboard (FR-VIEW-040, Polish — except Esc / Enter / arrows in the viewer, which are Core)

| Key                | Action                                                                                  |
| ------------------ | --------------------------------------------------------------------------------------- |
| ↑ ↓                | Move the selection                                                                      |
| Shift + ↑ ↓        | Extend the selection                                                                    |
| Enter              | Open folder / open the viewer                                                           |
| Backspace          | Go to the parent folder                                                                 |
| F2                 | Rename inline                                                                           |
| Delete             | Delete, with the BR-030 confirm                                                         |
| Ctrl/⌘ + A         | Select everything in the folder                                                         |
| Ctrl/⌘ + X / C / V | Cut, copy, paste                                                                        |

Focus is visible at every step, dialogs and the viewer trap focus and return it on close, and every
icon-only button has an `aria-label`.

## Flows worth spelling out

**Upload.** Files land in a queue rendered as a bottom-right card, one row per file with a
progress bar and a cancel button. Rows go green on completion and red with a Retry link on
failure. The card stays until dismissed, so a failure is not lost when the user navigates
away. Progress needs `XMLHttpRequest` — `fetch` reports no upload progress.

**View a file (FR-VIEW-060).** A full-screen overlay over the listing, not a pane: file name and
Download top-left, close top-right, `Esc` to leave, `←` / `→` to step through the other files in the
folder. PDFs render in an `<iframe>` on the presigned inline URL at full viewport height — the whole
point of a data room is reading documents, and a 320 px side pane cannot show a page of a contract.
Images are fitted with a dark backdrop. Everything else gets a type icon, the size, and a Download
button, which is honest rather than a broken embed.

**Move (FR-FILE-050 / FR-FLDR-040).** A dialog with the folder tree as a picker. The current parent
is disabled and labelled "current folder"; for a folder being moved, itself and its descendants are
disabled too, so `INVALID_MOVE` is unreachable from the UI and the rule is still enforced by the
server. Dragging onto a folder in the tree or the listing does the same thing without the dialog.

**Delete a folder.** The confirm dialog fetches `GET /nodes/:id/stats` before it opens and
renders the real numbers (BR-030). While the fetch is in flight the confirm button is disabled
rather than showing a guess. If the subtree has active shares, the dialog adds "this also revokes 2
links".

**Name conflict.** No prompt, no blocked dialog. The server renames per BR-020 and the toast
says which name was used, with the new item selected and scrolled into view.

**Share (FR-SHARE-010/020/060).** Opened from the toolbar, the context menu, or the header when
nothing is selected — that last one is how the **Data Room itself** gets shared, and the dialog says
"Anyone with the link can view **this entire Data Room**" so the blast radius is not a guess. Mode is
a two-option segmented control — Anyone with the link / Only a specific person, which reveals an
email field — plus an optional expiry. Creating a share copies the link to the clipboard
immediately, because that is the only reason anyone opened this dialog. Below the form: the existing
shares on this node, each with mode, grantee, expiry and a Revoke that asks once. If an ancestor is
already shared, a line says so and names it — otherwise the owner cannot tell why a file is exposed.

**Shared view (FR-SHARE-070).** A file share opens directly in the viewer, with no arrows and no close control (the shared viewer is not URL-addressable). A folder share shows the same three panes at `/s/{token}`, with the tree rooted at the shared node, a toolbar holding only Download and the view toggle, no context menu, and a header strip reading "Shared by _email_ · read only"; double-clicking a file row opens the viewer. Breadcrumbs stop at the shared root. A revoked, expired or deleted share renders one centred message — "This folder was removed by its owner" — never a raw error (FR-SHARE-050). A `RESTRICTED` link opened by a stranger shows a sign-in screen that says a link exists and nothing about what is behind it (`SIGN_IN_REQUIRED`).

**Shared with me (FR-SHARE-080).** A sidebar entry below the tree, listing restricted shares granted
to this email — item name, owner, granted date — each opening the shared view. Empty until someone
shares with you, and hidden entirely when the list is empty.

**Search (extra credit).** Typing filters into a results list that replaces the listing; the
breadcrumb bar shows `Search: "q"` with a Clear affordance. Selecting a hit navigates to the parent
folder and selects the item (FR-SRCH-010/020).

**Empty, loading, error.** An empty folder shows an illustration plus New folder and Upload. A
loading listing shows skeleton rows, never a spinner that shifts layout. A failed listing shows
an inline message with Retry (BR-050). Every one of the three is built with the listing in slice 4,
not retrofitted (FR-NAV-040).

## Theme (FR-VIEW-050, Polish)

One `:root` / `.dark` block of CSS custom properties in `apps/web/src/styles/tokens.css` — the
shadcn convention — consumed by Tailwind's `@theme` and by every component through utility classes.
No colour literals in components, so there is one place to change. The initial mode follows
`prefers-color-scheme`; the header toggle overrides it and persists to `localStorage`.

## Component inventory

The brief asks for granular components, so here is the decomposition rather than a promise of one.
Anything below is a file in `apps/web/src/components/<area>/`, takes props and holds no fetching
logic unless it is named `*Panel` or `*Screen`; data comes from hooks in `src/hooks/` that wrap
TanStack Query.

Three splits worth the argument: `FolderPicker` is separate from `FolderTree` because the picker's
disabled rules are the move rules, not navigation rules; `PdfViewer` is separate from `FileViewer`
so a switch to pdf.js touches one file; `DeleteImpact` is separate from `DeleteDialog` because it
owns the stats fetch that keeps the confirm button disabled.

## State ownership

Keeping these apart is what stops the selection and the cache from fighting:

- **TanStack Router** — which folder is open, whether the viewer is open and on which file, and the
  search term. The URL is the state (FR-NAV-020), so a viewer deep link is shareable and Back closes
  the viewer.
- **TanStack Query** — everything from the server. Keys: `['children', folderId]` (infinite),
  `['path', id]`, `['stats', id]`, `['shares', id]`, `['shares', 'received']`, `['search', q]`,
  `['usage', dataRoomId]`. A mutation invalidates `children` for the source and target folders,
  `usage`, and `stats` for every ancestor of both. `refetchOnWindowFocus` is on, which is what makes
  FR-SHARE-050 land for an idle viewer.
- **Zustand** — selection, clipboard (ids + cut/copy), view mode, theme, upload queue, expanded tree
  nodes. None of it is server truth; none of it belongs in the URL.
